# Исключения CRS

Файлы `*.conf` из этого каталога подключаются **после** `crs-setup.conf`,
но **до** правил CRS — это правильное место для `ctl:ruleRemoveById`
и прочих действий, которые должны отработать раньше самого правила.

Каталог монтируется томом, пересборка образа не нужна: правка файла +
reload nginx из панели.

Диапазон ID для собственных правил: 1000000–1999999.

## Как найти ID для исключения

Аудит-лог пишется в stdout контейнера в JSON:

```bash
docker compose logs nginx-ui | grep '"transaction"' | tail -5 | python3 -m json.tool
```

Нужное поле — `messages[].details.ruleId` и `data`.

## Примеры

Снять конкретные правила с эндпоинта, где ложные срабатывания ожидаемы:

```
SecRule REQUEST_URI "@beginsWith /api/upload" \
    "id:1000100,\
     phase:1,\
     pass,\
     nolog,\
     ctl:ruleRemoveById=920420,\
     ctl:ruleRemoveById=942100"
```

Снять правило только для одного параметра, а не целиком:

```
SecRule REQUEST_URI "@beginsWith /search" \
    "id:1000110,\
     phase:2,\
     pass,\
     nolog,\
     ctl:ruleRemoveTargetById=942100;ARGS:query"
```

Второй вариант почти всегда предпочтительнее: он оставляет правило
работать на остальных параметрах.

## Про 00-placeholder.conf

Не удаляйте его, пока в каталоге нет ваших правил: ModSecurity падает
с ошибкой `Not able to open file`, если `Include` с маской `*.conf`
не нашёл ни одного файла.

Свои правила кладите отдельными файлами — порядок подключения алфавитный,
поэтому удобно нумеровать: `10-...`, `20-...`.
